CLAUDE.md Project memory

프로젝트 기억을 먼저 심는다

프로젝트 루트의 Markdown 파일로, 같은 저장소에서 세션을 시작할 때마다 Claude가 자동으로 읽는다. 빌드 명령·컨벤션·아키텍처·금지사항을 적어두면 매번 다시 설명할 필요가 없다. /init으로 생성한다.

사용 시점
새 저장소를 시작할 때, 또는 주요 구조 변경 직후
담을 내용
스택·버전, 실행/테스트/빌드 명령, 비자명한 컨벤션 1~2개, "하지 말 것"
주의
길수록 좋은 게 아님 — 간결하게. /memory로 편집하고 git에 커밋해 팀과 공유
실전 예시
/init → 생성된 CLAUDE.md를 열어 스택·금지사항을 직접 보강
/plan Plan first

코드를 건드리기 전 계획부터

플랜 모드에서는 Claude가 읽고 분석만 하며 파일을 수정하지 않는다. 계획을 검토·승인한 뒤 일반 모드로 돌아와 구현을 지시한다. 낯선 코드일수록 효과가 크다.

사용 시점
낯선 코드베이스, 큰 리팩터링 전, 여러 파일에 걸친 변경
진입 방법
Shift+Tab으로 권한 모드 순환 (default → acceptEdits → auto → plan) 또는 /plan
연계
계획 승인 후 일반 모드로 전환 → "계획대로 구현해"
실전 예시
Shift+Tab → plan 모드 → "src/auth 흐름을 보고 Google 로그인을 추가할 위치를 제안해"
/effort Right effort

작업 난도에 맞춰 추론 강도를 맞춘다

한 작업에 쏟는 추론량을 조절한다. 모든 작업에 max를 쓰면 느리고 토큰만 많이 든다 — 난도에 맞추는 것이 핵심이다.

사용 시점
빠른 반복은 low, 아키텍처·보안 분석·에이전트 루프는 high 이상
단계
low / medium / high / xhigh / max / auto — xhigh는 Opus 4.7+ 전용
주의
인자 없이 실행하면 인터랙티브 슬라이더. 스킬·슬래시 명령 frontmatter로 개별 지정 가능
실전 예시
/effort xhigh — Opus 4.7의 코딩·에이전트 작업에 권장되는 기본값
/review Quality gate

머지 전 동작과 보안을 점검한다

/review는 변경된 코드를 코드 리뷰 관점에서 점검하고, /security-review는 변경분(diff)에서 취약점을 찾는다. 변경된 코드만 분석해 빠르다.

사용 시점
커밋·PR·배포 전 마지막 검토 단계
초점
/review는 로직·회귀·빠진 테스트, /security-review는 인젝션·인증 우회 등
연계
/diff로 실제 파일 변경을 확인, /pr-comments로 리뷰어 코멘트 반영
실전 예시
/review → /security-review → /diff
/compact Keep going

컨텍스트를 압축해 세션을 이어간다

대화가 길어지면 히스토리를 요약 압축해 컨텍스트 공간을 확보한다. /clear와 달리 무엇을 논의했는지 맥락의 줄기는 보존된다.

사용 시점
컨텍스트 70~75%에서 — 경고가 뜰 때까지 기다리지 말 것 (한계 근처에서 성능 저하)
핵심 요령
항상 보존 지시를 함께 — 지시가 없으면 일반 요약이 되어 중요한 맥락이 사라진다
연계
/context로 사용량을 점검해 압축 시점을 판단
실전 예시
/compact 인증 리팩터링 결정만 유지, 마이그레이션 파일은 무시
/rewind Safety net

잘못된 길은 체크포인트로 되돌린다

Esc를 두 번 누르면 리와인드 메뉴가 열린다. 코드와 대화를 이전 체크포인트로 복원할 수 있다 — git stash보다 빠른 실험 안전망. 메뉴의 여기까지 요약은 최근 턴은 그대로 두고 이전 컨텍스트만 압축한다.

사용 시점
Claude가 엉뚱한 방향으로 갈 때, 실험이 실패했을 때
3가지 옵션
대화만 / 코드만 / 둘 다 — "코드만"이 핵심 (대화는 남아 무엇을 왜 시도했는지 기억)
주의
Ctrl+C는 중단일 뿐 되돌리기가 아님 — 되돌리려면 Esc Esc
실전 예시
Esc Esc → 메뉴에서 "Restore code only" 선택
