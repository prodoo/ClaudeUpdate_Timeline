STEP 1 — 2 · 구조 이해

언제·어디를 가로챌지 안다

Hooks가 settings.json에서 어떻게 동작하는지, 생명주기 이벤트가 어느 케이던스로 발동하는지 파악한다.

STEP 3 — 4 · 핵심 두 갈래

막을 건 막고, 치울 건 치운다

PreToolUse로 위험한 동작을 실행 전에 차단하고, PostToolUse로 포맷·린트를 사후 자동화한다.

STEP 5 — 6 · 심화와 안전

정밀하게, 그리고 안전하게

4종 핸들러와 JSON 출력으로 정밀 제어하고, 샌드박스가 없다는 전제 위에서 안전 장치를 건다.

settings.json Deterministic

반복 작업을 settings.json에 박제한다

Hooks는 Claude Code 생명주기의 특정 시점에 자동 실행되는 사용자 정의 핸들러다. 프롬프트·스킬과 달리 AI 판단에 의존하지 않고, 정해진 일이 항상 일어나도록 보장한다.

설정 위치
.claude/settings.json(프로젝트) / ~/.claude/settings.json(글로벌)
구성 3요소
이벤트(언제) + matcher(어떤 도구·파일) + command(무엇을 실행)
진입 방법
/hooks로 인터랙티브 설정 — 이벤트 → matcher → 명령 선택. 또는 JSON 직접 편집
실전 예시
PostToolUse + matcher "Edit|Write" + prettier — 파일을 고칠 때마다 자동 포맷
lifecycle events Event map

생명주기 이벤트를 케이던스로 나눠 잡는다

이벤트는 발생 주기로 묶인다. 어느 시점을 가로챌지가 자동화 설계의 출발점이다 — 2026년 3월 기준 약 21개 이벤트가 세션 시작부터 끝까지를 덮는다.

세션당
SessionStart · SessionEnd — 환경 준비, 정리
턴당
UserPromptSubmit · Stop · StopFailure — 입력 검증, 완료 게이트
도구마다
PreToolUse · PostToolUse (+PostToolUseFailure, SubagentStop, PreCompact, MessageDisplay 등)
실전 예시
SessionStart 훅이 git 브랜치·TODO를 출력 → Claude 컨텍스트로 주입
PreToolUse Block & gate

위험한 동작을 실행 전에 막는다

PreToolUse는 도구가 실행되기 전에 발동하며, 차단·입력 수정·컨텍스트 추가가 가능한 유일한 훅이다. exit 2가 핵심 — 도구 호출이 멈추고 stderr가 Claude에게 에러로 전달된다.

matcher
Bash·Edit·Write·Read·Grep 등, MCP 도구는 mcp__server__tool
차단 원리
exit 2 → 도구 차단 / exit 0 → 통과. exit 1은 경고만 (차단 안 됨)
주의
매칭되는 모든 도구 호출마다 동기 실행 — 500ms 이내로 빠르게 유지
실전 예시
PreToolUse + Bash — rm -rf·DROP TABLE 감지 시 exit 2로 차단
PostToolUse Auto cleanup

도구 실행 후 결과를 자동으로 정리한다

PostToolUse는 도구가 성공적으로 끝난 뒤에 발동한다. 이미 실행된 동작을 되돌릴 순 없지만 포맷·린트·로깅·사후 검증에 완벽하다. 모델 출력과 무관하게 포맷터가 모든 걸 정규화한다.

입력
tool_input(보낸 인자) + tool_response(반환 결과)를 모두 받음
대표 패턴
Write|Edit에 포맷터+린터 — 한 이벤트의 여러 훅은 병렬 실행
멱등성
매 편집마다 돌려도 안전하게 설계. 무거우면(>500ms) 세션이 느려진다
실전 예시
PostToolUse + "Write|Edit|MultiEdit" — prettier·eslint로 자동 포맷·수정
4 handler types Precise control

핸들러 4종과 JSON으로 정밀 제어한다

단순 셸 검사부터 의미 판단까지 — 용도에 맞는 핸들러를 고른다. JSON 출력으로 권한 결정·입력 재작성·컨텍스트 주입까지 훅이 직접 돌려줄 수 있다.

4종
command(셸; args:[] exec 형식은 셸 없이 직접 실행) / http(엔드포인트 POST) / prompt(경량 Claude 판단) / agent(도구 접근 심층 분석)
JSON 제어
permissionDecision(allow/deny/ask) · updatedInput(입력 수정) · additionalContext(주입) · continueOnBlock(거부 사유 피드 후 계속) · terminalSequence(알림·벨·창 제목)
async
async: true — 로그·알림·백업은 백그라운드로, Claude 실행을 막지 않음
실전 예시
http 훅으로 팀 공통 정책을 원격 검증 서버에 위임 → 응답 JSON으로 allow/deny
safe by design No sandbox

훅은 샌드박스 없이 도는 걸 전제로 운용한다

훅은 사용자 전체 권한으로 실행되며 샌드박스가 없다 — 잘못 짠 훅은 파일을 지우거나 비밀을 노출할 수 있다. 안전은 기대가 아니라 설정으로 강제한다.

조직 통제
allowManagedHooksOnly로 승인된 훅만 허용, disableAllHooks로 전체 비활성
재귀 적용
서브에이전트의 도구 호출에도 훅이 발동 — 가드레일이 재귀적으로 적용된다
권한 자동화
/less-permission-prompts(v2.1.111)로 안전한 읽기 전용 호출 allowlist 자동 제안
실전 예시
# 신뢰 못 할 플러그인 훅은 검토 전 실행 금지 — 직접 읽어보고 승인
보조 · 명령어 기반 자동화

훅이 이벤트를 가로챈다면, 이쪽은 시간·반복으로 건다

Hooks가 도구 호출 이벤트에 반응하는 자동화라면, /loop는 세션 내 반복 실행을, /schedule은 Anthropic 관리 클라우드의 예약 실행(routines)을 담당한다. 훅과 보완 관계이며, 두 명령어는 전체 명령어 시트에서도 확인할 수 있다.

/loop Repeat in-session

세션이 열린 동안 반복 실행한다

/loop [간격]은 Skill로, 세션이 살아 있는 동안 프롬프트를 반복 실행한다. 간격을 생략하면 Claude가 반복 사이 속도를 자동 조절하고, 프롬프트를 생략하면 자동 유지 관리 검사 또는 .claude/loop.md의 프롬프트를 실행한다. 별칭 /proactive.

실행 위치
현재 로컬 세션 내 — 세션이 닫히면 멈춘다
간격
5m처럼 지정하거나 생략 시 자동 페이스
프롬프트
생략 시 자동 유지 관리 또는 .claude/loop.md 실행
실전 예시
/loop 5m check if the deploy finished
/schedule Cloud routines

클라우드에서 예약 실행한다 — routines

/schedule은 routines를 만들고 갱신·나열·실행한다. Anthropic 관리 클라우드에서 돌기 때문에 로컬 머신이 꺼져 있어도 동작한다. Claude가 설정 과정을 대화형으로 안내한다. 별칭 /routines.

실행 위치
Anthropic 관리 클라우드 — 로컬 종료와 무관
진입
대화형 안내. GitHub 미연결 시 /web-setup 자동 요청
트리거 구분
repo 이벤트는 Actions, 시간 기반은 /schedule
실전 예시
/schedule 매일 오전 9시에 빌드 상태 확인
