Codex CLI Playbook · 02

한 작업 완주 계획부터 검증까지 한 흐름

계획을 세우고, 실행 중 방향을 잡고, 바뀐 것을 확인하고, 리뷰로 거르고, 컨텍스트를 정리해 다음으로 잇는다 — 작업 하나를 끝까지 끌고 가는 6단계.

STEP 1—2

계획하고 끼어들기

plan 모드로 실행 계획을 먼저 받고, 작업이 도는 중에는 Enter·Tab으로 방향을 잡는다.

STEP 3—4

확인하고 거르기

/diff로 바뀐 파일을 살피고, /review로 커밋 전 셀프 리뷰를 돌린다.

STEP 5—6

정리하고 잇기

/compact로 긴 대화를 압축하고, /resume로 다음 세션에 이어간다.

/plan Plan first

계획부터 세우기

/plan을 입력하면 활성 대화가 plan 모드로 전환돼, Codex가 구현에 들어가기 전 실행 계획을 먼저 제안한다. /plan 서비스 마이그레이션 계획 세워줘처럼 인라인 프롬프트를 붙일 수 있고, 그 상태에서 내용을 붙여넣거나 이미지를 첨부할 수도 있다.

사용 시점구현에 들어가기 전 접근법을 먼저 합의하고 싶을 때
인라인 인자/plan <지시> — 첫 계획 요청으로 사용. 텍스트·이미지 첨부 가능
주의작업이 이미 실행 중이면 /plan은 일시적으로 사용 불가
실전 예시
> /plan 인증 모듈 리팩터링 계획 ▸ 단계별 실행 계획 제시 ▸ 단계마다 승인·거부 # 인라인 검토
Enter · Tab Steer mid-run

실행 중 끼어들기

Codex가 도는 중에 Enter를 누르면 현재 턴에 새 지시를 밀어 넣고, Tab을 누르면 다음 턴으로 입력을 큐에 넣는다. 큐에 넣는 입력은 일반 프롬프트, /review 같은 슬래시 명령어, ! 셸 명령어 모두 가능하다. 작성 칸에서 ↑ ↓ 로 이전 초안을 오갈 수도 있다.

진입 방법Codex 실행 중 작성 칸에 입력 후 Enter 또는 Tab
Enter vs TabEnter = 현재 턴에 즉시 주입 / Tab = 다음 턴 큐에 적재
연계큐에 /review·!cmd도 가능. 큐된 슬래시는 실행 시점에 파싱
실전 예시
실행 중... Enter 현재 턴에 지시 주입 Tab 다음 턴 큐에 적재
/diff See the changes

바뀐 것 확인하기

/diff는 Git diff를 CLI 안에서 보여 준다 — 스테이징한 변경, 아직 스테이징 안 한 변경, 그리고 Git이 아직 추적하지 않는 새 파일까지 포함한다. 무엇을 남기고 무엇을 버릴지 커밋·테스트 전에 판단하는 용도다.

사용 시점Codex가 편집을 끝낸 뒤, 커밋·테스트에 들어가기 전
포함 범위스테이징됨 / 안 됨 / 미추적 신규 파일까지 전부
연계한 번 더 눈이 필요하면 /review와 함께. Git 명령은 그대로 병행
실전 예시
> /diff M src/auth.ts # 변경됨 ?? src/auth.test.ts # 미추적 신규
/review Quality gate

커밋 전 셀프 리뷰

/review는 Codex에게 작업 트리를 리뷰시킨다. 동작 변경과 누락된 테스트에 초점을 맞춰 문제를 요약해 준다. 기본적으로 현재 세션 모델을 쓰지만, config.toml에 review_model을 지정하면 그 모델로 리뷰한다.

사용 시점Codex가 작업을 끝냈을 때, 또는 로컬 변경에 한 번 더 눈이 필요할 때
검토 초점동작 변경, 누락된 테스트
설정review_model로 리뷰 전용 모델 지정. 팀 규칙은 code_review.md
실전 예시
> /review ⚠ 엣지 케이스 미처리 # 동작 변경 지적 > /diff 정확한 변경 확인
/compact Keep it lean

긴 대화 압축하기

긴 작업 뒤 /compact를 쓰면 Codex가 이전 턴들을 간결한 요약으로 대체해, 핵심 정보는 유지하면서 컨텍스트 창을 비운다. Codex는 대화를 자동으로도 압축하므로, /compact는 수동으로 시점을 당기고 싶을 때 쓴다.

사용 시점스레드가 길어져 컨텍스트 창이 빠듯할 때
동작이전 턴 → 요약으로 치환, 핵심 디테일은 유지
주의Codex가 자동 압축도 수행 — /compact는 수동 트리거
실전 예시
> /compact ▸ 이전 대화 요약 생성 # 핵심만 보존 ▸ 컨텍스트 여유 확보
/resume Pick it back up

다음에 이어가기

/resume를 입력하면 저장된 세션 목록에서 골라 그 대화의 전체 transcript를 다시 불러온다 — 원래 히스토리는 그대로 둔 채 이어서 작업한다. 새 맥락이 필요하면 /new, 분기해 다른 접근을 시험하려면 /fork. 저장된 세션을 분기·복원하려면 셸에서 codex fork·codex resume.

진입 방법세션 중 /resume → 저장 세션 피커에서 선택
vs /new·/fork/new 같은 세션 내 새 대화 / /fork 현재 대화 분기
주의저장된 세션 분기·복원은 셸 codex fork·codex resume (Playbook ④ 참고)
실전 예시
> /resume ▸ 저장 세션 피커 # transcript 복원 $ codex resume 셸에서 직접
6단계 아크
계획 → 끼어들기 → 변경 확인 → 리뷰 → 압축 → 이어가기
한 작업을 이 흐름으로 돌리면, 권한·자동화·멀티스레드 플레이북의 고급 기법도 같은 사이클 위에 얹힌다.
