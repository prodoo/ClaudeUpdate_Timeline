codex exec Run headless

비대화형으로 실행

codex exec "작업 설명"은 대화형 TUI를 열지 않고 Codex를 한 번 돌린다 — 별칭은 codex e. 결과를 stdout 또는 JSONL로 스트리밍하고, 이전 세션을 이어받을 수도 있다. 스크립트·크론·CI에 그대로 박아 넣는 진입점이다.

사용 시점사람의 개입 없이 정해진 작업을 1회 실행할 때
별칭·인자codex e "..." — 글로벌 플래그는 서브커맨드 뒤에 (codex exec --oss ...)
주의제출 실패 시 non-zero로 종료 — CI에서 실패 감지에 활용 가능
실전 예시
$ codex exec "실패한 파서 테스트 고쳐줘" $ codex e "린트 에러 정리" \ --sandbox workspace-write # 편집 허용
--json · --output-last-message Machine-readable

결과를 기계가 읽게

--json을 붙이면 Codex가 줄 단위 JSON 이벤트(JSONL)를 내보내, 프로그램이 진행 상황을 파싱할 수 있다 — 추론 토큰 사용량도 보고된다. --output-last-message는 최종 응답만 파일로 저장한다. 후속 파이프라인 단계가 결과를 받아 쓰기 좋다.

사용 시점exec 결과를 다른 스크립트·도구가 소비해야 할 때
출력 형태--json 줄 단위 JSON 이벤트 / --output-last-message 최종 응답 파일
연계codex exec와 함께. 인증은 기존 CLI 로그인을 따름
실전 예시
$ codex exec "릴리스 노트 작성" --json \ --output-last-message out.md {"type":"item.completed",...} # JSONL 스트림
--sandbox · -a never Lock it down for CI

CI용 권한 고정

CI처럼 사람이 없는 환경에선 권한을 명시적으로 박아야 한다. --sandbox로 모델 셸 명령의 샌드박스 정책을(예: workspace-write), -a / --ask-for-approval로 승인 시점을 정한다. 비대화형은 never가 권장값 — 멈춰서 물어볼 사람이 없기 때문이다.

사용 시점CI·크론 등 무인 실행 파이프라인
권장 조합--sandbox workspace-write + -a never (비대화형 기준)
주의on-failure 승인 모드·--full-auto는 deprecated — 명시적 플래그 사용 (상세는 ⑤)
실전 예시
$ codex exec "마이그레이션 적용" \ --sandbox workspace-write -a never # 멈춤 없이 끝까지 실행
codex mcp Wire external tools

외부 도구 연결

codex mcp 명령으로 Model Context Protocol 서버를 등록하면, Codex가 세션 시작 시 자동으로 띄워 그 도구들을 빌트인 옆에 노출한다. STDIO·streaming HTTP 서버를 ~/.codex/config.toml에 직접 적거나 codex mcp add로 추가한다. Codex 자체를 MCP 서버로 돌릴 수도 있다.

진입 방법codex mcp add <이름> <URL> 또는 config.toml 직접 편집
설정 위치~/.codex/config.toml의 mcp_servers — 세션 시작 시 자동 기동
주의필요한 도구만 1~2개부터. 세션 내 확인은 /mcp(verbose로 상세)
실전 예시
$ codex mcp add db-tools https://... # 세션에서 확인 > /mcp verbose 연결된 서버·도구 표시
Skills · Hooks Package the workflow

워크플로 패키징

반복되는 작업은 길어진 프롬프트 대신 Skill로 묶는다 — SKILL.md에 지시·맥락·보조 로직을 담으며, CLI·IDE·App에서 공통으로 동작한다. Hooks는 정식 기능으로, 특정 이벤트에 스크립트를 거는 설정 기반 자동화다. 각 Skill은 한 가지 일에만 좁게 맞춘다.

무엇인가Skill = SKILL.md 패키지 / Hooks = 이벤트 트리거 스크립트
적용 범위Skill은 CLI·IDE·App 공통. Hooks는 config 기반, 플러그인 번들 가능
연계Skill은 2~3개 구체 유스케이스부터, "무엇을·언제"를 description에 명시
실전 예시
# .codex/skills/release/SKILL.md name: release-notes description: PR 묶어 릴리스 노트 생성
codex cloud · apply Offload to cloud

클라우드로 넘기기

무거운 작업은 codex cloud(별칭 codex cloud-tasks)로 Codex Cloud 작업을 띄워 터미널을 떠나지 않고 탐색·실행한다. 환경은 Ctrl+O로 고른다. 완료된 작업의 diff는 codex apply(별칭 codex a)로 로컬 작업 트리에 가져온다.

진입 방법codex cloud로 작업 띄우기·탐색, Ctrl+O로 환경 선택
흐름클라우드 작업 실행 → diff 생성 → codex apply로 로컬 반영
주의환경 ID는 Codex cloud 설정에서 옴 — 정확한 값은 대시보드로 확인
실전 예시
$ codex cloud # 작업 띄우고 환경 선택 $ codex apply # 결과 diff를 로컬에 적용
6단계 아크
헤드리스 실행 → 기계가 읽는 출력 → CI 권한 고정 → 외부 도구 → 패키징 → 클라우드 위임
사람이 붙어 있던 ②편의 사이클을 무인 파이프라인으로 옮기는 단계 — 권한 고정의 디테일은 ⑤편에서 더 판다.
