Codex CLI Playbook · 01

환경 세팅 처음 켜서 일할 환경 만들기

설치·인증부터 권한 정책, AGENTS.md, config.toml까지 — Codex CLI가 당신의 저장소에서 안전하게 일하도록 바닥을 까는 6단계.
codexInstall & sign in
/model · /fastPick the engine
/permissionsSet the guardrails
/initPersist instructions
config.tomlTune defaults
/statusVerify setup
STEP 1—2

켜고 들어가기

npm으로 설치하고 ChatGPT 계정 또는 API 키로 인증한 뒤, 작업 성격에 맞는 모델과 속도를 고른다.

STEP 3—4

정책과 지침 깔기

승인·샌드박스 정책을 정하고, AGENTS.md로 저장소 컨벤션을 고정해 모든 세션이 같은 맥락을 공유하게 한다.

STEP 5—6

기본값 굳히고 검증

config.toml로 기본값을 박아 두고, /status·/debug-config로 설정이 의도대로 먹었는지 확인한다.

codex Install & sign in

설치하고 로그인하기

npm i -g @openai/codex로 설치하고 터미널에서 codex를 실행하면 첫 실행 때 로그인 화면이 뜬다. ChatGPT 계정(Plus·Pro·Business·Edu·Enterprise 포함) 또는 API 키 중 하나로 인증한다. Codex CLI는 macOS·Windows·Linux를 지원하며 Rust로 작성된 오픈소스다.

설치npm i -g @openai/codex 또는 brew install --cask codex
인증codex 실행 → Sign in with ChatGPT, 또는 API 키
주의Windows는 네이티브 PowerShell(샌드박스) 또는 WSL2. 업데이트는 codex update
실전 예시
$ npm i -g @openai/codex $ codex # 첫 실행 → 로그인 안내 > Sign in with ChatGPT
/model · /fast Pick the engine

모델과 속도 고르기

세션 안에서 /model로 활성 모델과 추론 강도를 바꾼다 — GPT-5.5·GPT-5.4·GPT-5.3-Codex 등에서 선택. /fast는 지원 모델에서 Fast 모드를 켜고 끈다. TUI에서는 Alt+, / Alt+. 로 추론 강도를 즉시 낮추거나 올릴 수도 있다.

사용 시점빠른 모델 ↔ 깊은 추론 모델을 작업 성격에 맞춰 전환할 때
선택지/model(모델·추론 강도), /fast on|off|status
연계변경 확인은 /status, 푸터 상시 표시는 /statusline
실전 예시
> /model # 팝업에서 모델 선택 > /fast on # Fast 모드 켜기 > /status # 적용 확인
/permissions Set the guardrails

승인·샌드박스 정책 잡기

/permissions로 Codex가 묻지 않고 할 수 있는 범위를 정한다. 검토 위주면 Read Only, 맡기는 작업이면 Auto 같은 프리셋을 고른다. 승인 모드와 샌드박스 모드는 별개 손잡이이며, 새로 시작할 땐 기본값으로 두고 신뢰하는 저장소에서만 풀어주는 게 안전하다.

사용 시점세션 도중 승인 강도를 조이거나 풀어줄 때
모드Read Only / Auto 등 프리셋 — /approvals는 별칭(팝업 비표시)
주의자세한 권한 설계는 Playbook ⑤에서. on-failure 승인 모드는 deprecated
실전 예시
> /permissions ▸ Read Only # 편집 전 검토 ▸ Auto # 핸즈오프 실행
/init Persist instructions

AGENTS.md로 맥락 고정

/init을 실행하면 현재 디렉터리에 AGENTS.md 스캐폴드가 생성된다. 저장소 컨벤션·빌드 방법·주의사항을 여기 적어 두면 이후 모든 세션이 같은 맥락을 공유한다. 생성된 파일을 다듬어 커밋하는 흐름이다.

진입 방법맥락을 둘 디렉터리에서 /init 실행
담는 내용빌드·테스트 명령, 코드 컨벤션, 하지 말 것
주의하위 디렉터리별로도 둘 수 있음. 팀 리뷰 규칙은 code_review.md 분리 권장
실전 예시
> /init # AGENTS.md 생성 # 내용 편집 후 커밋 $ git add AGENTS.md
config.toml Tune defaults

config.toml로 기본값 조정

Codex는 기본값을 ~/.codex/config.toml에서 읽는다. 모델·승인 정책·샌드박스·MCP 서버· tui.status_line 같은 항목을 미리 박아 두면 매번 슬래시로 바꿀 필요가 없다. CLI에서 -c key=value로 그때그때 덮어쓸 수도 있다.

위치~/.codex/config.toml (CODEX_HOME 설정 시 그 경로)
핵심 키model, 승인·샌드박스, mcp_servers, tui.status_line, [features]
연계일회성 오버라이드는 -c key=value. CLI·IDE·App이 같은 설정을 공유
실전 예시
# ~/.codex/config.toml model = "gpt-5.5" $ codex -c model=gpt-5.4 # 1회 덮어쓰기
/status · /debug-config Verify setup

설정이 먹었는지 확인

/status는 활성 모델·승인 정책·쓰기 가능 루트·토큰 사용량을 한 화면에 보여 준다. 설정이 의도대로 안 먹을 땐 /debug-config로 설정 레이어 우선순위와 정책 출처를 들여다본다 — config.toml 값과 실제 적용값이 왜 다른지 추적하는 용도다.

사용 시점작업 시작 전, 또는 설정이 의심스러울 때
확인 항목모델·승인 정책·쓰기 루트·토큰 / 설정 레이어 우선순위
트러블슈팅/debug-config로 allowed_* 정책·experimental 제약 확인
실전 예시
> /status # 모델·정책·토큰 요약 > /debug-config # 레이어·정책 출처 진단
6단계 아크
설치·인증 → 모델·속도 → 권한·샌드박스 → AGENTS.md → config.toml → 검증
한 번 깔아 두면 이후 플레이북(작업 완주 · 자동화 · 멀티스레드 · 권한 심화)이 모두 이 바닥 위에서 돈다.
