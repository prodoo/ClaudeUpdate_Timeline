Codex CLI Playbook · 04

컨텍스트·멀티스레드 대화 흐름 관리

한 터미널에서 여러 갈래의 작업을 흩어지지 않게 다룬다 — 새 대화, 분기, 곁가지, 서브에이전트, 세션 복원, 상태 표시까지 대화 흐름을 손에 쥐는 6단계.
/new · /clearFresh start
/forkBranch the thread
/sideQuick detour
/agentSwitch agents
/resumeReload a session
/title · /statuslineTrack at a glance
STEP 1—2

새로 열고 가지치기

/new·/clear로 깨끗한 대화를 시작하고, /fork로 현재 대화를 분기해 다른 접근을 병행한다.

STEP 3—4

곁가지와 에이전트

/side로 본 작업을 떠나지 않고 곁가지 질문을 던지고, /agent로 서브에이전트 스레드를 넘나든다.

STEP 5—6

복원하고 표시하기

/resume로 저장된 세션을 되살리고, /title·/statusline으로 지금 상태를 한눈에 본다.

/new · /clear Fresh start

새 대화 시작하기

둘 다 같은 CLI 세션 안에서 새 대화를 시작하지만 화면 처리가 다르다. /clear는 터미널 화면까지 비우고 새 대화를 연다. /new는 화면은 그대로 둔 채 대화 맥락만 새로 시작한다. Ctrl+L은 화면만 지우고 대화는 유지하므로 헷갈리지 말 것. 작업 실행 중에는 둘 다 비활성화된다.

차이/clear 화면+대화 리셋 / /new 대화만(화면 유지) / Ctrl+L 화면만
사용 시점같은 저장소에서 다른 작업으로 갈아탈 때
주의작업이 도는 중에는 /clear·/new 둘 다 사용 불가
실전 예시
> /clear # 화면+대화 새로 > /new # 대화만 새로, 화면 유지 Ctrl+L 화면만, 대화 유지
/fork Branch the thread

대화 분기하기

/fork는 현재 대화를 새 ID의 스레드로 복제한다 — 원본 transcript는 손대지 않으므로, 한 갈래는 그대로 두고 다른 접근을 병렬로 시험할 수 있다. 최신 턴뿐 아니라 이전 메시지 지점에서도 분기할 수 있다. 저장된(현재가 아닌) 세션을 분기하려면 셸에서 codex fork.

사용 시점지금까지의 맥락은 살리고 다른 길을 따로 파보고 싶을 때
동작현재 대화 → 새 ID 스레드로 복제, 원본 유지. 과거 메시지 지점 분기 가능
vs codex fork셸 codex fork는 저장된 세션 피커를 열어 분기
실전 예시
> /fork ▸ 새 스레드 ID로 복제 # 원본은 그대로 $ codex fork 저장 세션 분기
/side Quick detour

곁가지 질문하기

/side는 본 작업에서 화면을 떠나지 않고 휘발성 곁가지 대화를 연다 — transcript가 부모 스레드와 분리돼, 집중된 후속 질문 하나를 던지고 돌아올 수 있다. 인라인 텍스트 (/side 이 계획에 빤한 리스크 있나?)도 가능. side 모드에서는 부모 스레드 상태가 계속 보인다.

사용 시점본 흐름을 흩뜨리지 않고 짧게 확인하고 싶을 때
동작부모와 분리된 휘발성 대화, side 중에도 부모 상태 표시
제약다른 side 대화 안에서·review 모드에서는 사용 불가
실전 예시
> /side 이 접근에 빤한 함정 있나? ▸ 부모와 분리된 곁가지 ▸ 부모 상태는 계속 표시 # 돌아오면 그대로
/agent Switch agents

서브에이전트 넘나들기

병렬로 서브에이전트를 돌릴 때 /agent로 활성 스레드를 바꿔, 특정 에이전트가 한 작업을 들여다보거나 이어받는다. 본 에이전트는 핵심 문제에 집중시키고, 탐색·테스트·트리아지처럼 경계가 분명한 일은 서브에이전트에 떼어 주는 게 권장 패턴이다.

사용 시점병렬 에이전트를 돌리며 활성 스레드를 전환할 때
연계subagent 워크플로로 경계 있는 작업(탐색·테스트·트리아지) 분리
주의본 에이전트는 핵심 문제에 집중 — 같은 문제면 한 스레드 유지가 나음
실전 예시
> /agent ▸ 스레드 피커에서 선택 # 활성 스레드 전환 ▸ 서브에이전트 작업 확인·이어받기
/resume Reload a session

저장된 세션 복원

/resume는 저장된 세션 목록에서 골라 그 대화의 transcript를 다시 불러온다 — 원래 히스토리는 그대로 둔 채 이어 간다. 세션은 ~/.codex/sessions에 보관된다. 셸에서 바로 고르려면 codex resume. (작업 사이클 관점의 /resume은 ②편 참고.)

진입 방법세션 중 /resume → 저장 세션 피커 / 셸 codex resume
동작선택한 대화 transcript 복원, 원본 히스토리 유지
연계세션 저장 위치 ~/.codex/sessions. 분기는 /fork·codex fork
실전 예시
> /resume ▸ 저장 세션 피커 # transcript 복원 $ codex resume 셸에서 바로 선택
/title · /statusline Track at a glance

한눈에 상태 보기

/statusline은 TUI 푸터에 띄울 항목을 고르고 순서를 잡는다 — 모델·컨텍스트 통계·rate limit·git 브랜치·토큰·세션 ID·디렉터리·버전 등. /title은 터미널 창·탭 제목 항목을 고른다 — 프로젝트·상태·스레드·브랜치·모델·작업 진행률 등. 둘 다 즉시 반영되고 config.toml에 저장된다.

진입 방법/statusline / /title → 피커에서 토글·재정렬 후 확정
표시 항목푸터 = 모델·컨텍스트·토큰·브랜치 등 / 제목 = 프로젝트·상태·스레드 등
저장 위치tui.status_line / tui.terminal_title (config.toml)
실전 예시
> /statusline # 푸터 항목 선택 > /title # 창·탭 제목 항목 선택 # config.toml에 자동 저장
6단계 아크
새 대화 → 분기 → 곁가지 → 서브에이전트 → 세션 복원 → 상태 표시
여러 갈래가 동시에 도는 작업도 흐름이 보이면 흩어지지 않는다 — 다음은 권한·보안을 깊게 파는 ⑤편.
